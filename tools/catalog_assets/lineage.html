How lineage works

Lineage is declared by hand in the data contracts. It is not parsed from SQL, and nothing is run against the warehouse.

1. Declare column lineage in the contract

Each customer field says where it comes from:

- name: first_order_at
  logicalType: timestamp
  physicalType: TIMESTAMP
  transformLogic: transform
  transformSourceObjects:
    - raw__orders__shopify#orders.created_at
  transformDescription: Plus ancienne date de création parmi les commandes du client.
  customProperties:
    - property: transformExpression
      value: MIN(created_at)

A source reference reads <contract_id>#<object>.<property>. Nested fields use the full path.

transformLogicSourcesSQL expression
mapexactly oneoptional, rename or trivial cast only
transformat least onerequired, exact BigQuery SQL
createnoneoptional

Raw fields are map from the external system (for example shopify_admin_api#...). The technical fields meta_loaded_at and meta_source_file are create.

2. Table lineage is derived

There is no separate table-level declaration. A contract depends on another as soon as one of its columns references one of that contract's columns.

External source systems are not contracts, so they do not appear as nodes in the graph.

The graph legend is computed from the declaration: Pass-through is a map that keeps the name, Rename a map that changes it, Transformation a transform.

3. Checks before publication

make check validates the contracts. For lineage it verifies that:

  • every referenced contract, object and property exists;
  • a customer contract references raw contracts only;
  • there is no cycle;
  • transformLogic, its sources and its expression are consistent;
  • every customer field has transformLogic and transformDescription.

The SQL expressions are not executed: a valid reference does not prove that the pipeline really does what the contract says.

4. How it is exposed

make catalog reads the contracts and writes, among others:

  • colibri-manifest.json: contracts, columns, column-to-column and contract-to-contract edges, parents and children. Other tools can read it.
  • index.html: this catalog, a static dashboard built on dbt-colibri (MIT).

In the catalog, use the lineage view to follow tables and columns upstream and downstream. Open a column and turn on Expert mode to see its transformation description and SQL.

Every push to main runs the checks, rebuilds the catalog and deploys it to Cloudflare Pages when the deployment token is configured.

How lineage works

Lineage says where a number comes from and what breaks if you change a field. It comes down to one rule: each declared source becomes a link between two columns.

Data contract: a YAML file describing a table. Raw: a table copied from a system (Shopify, GA4…). Customer: a table computed from raw ones.

1. Declare a column

Example: spend_amount, the monthly ad spend, adds up Google Ads and Meta Ads.

# contracts/customer/acquisition/acquisition_monthly.odcs.yaml (excerpt)
- name: spend_amount
  transformLogic: transform
  transformSourceObjects:
    - raw__ad_spend__googleads#ad_spend.metrics_cost_micros
    - raw__ad_spend__metaads#ad_spend.spend
    # + 8 (10 sources)
  transformDescription: Somme des micros Google Ads divises par 1 000 000 et de la depense Meta decimale, en EUR.
  customProperties:
    - property: transformExpression
      value: IFNULL(SUM(spend_eur), 0)
  • transformSourceObjects: every column used, including to filter or join. This is the only thing that draws the graph.
  • transformDescription: one sentence anyone can read.
  • transformExpression: the BigQuery SQL. It is neither run nor compared with the sources; here spend_eur is an intermediate name.
transformLogicWhenSourcesSQL
mapvalue copiedexactly oneoptional: simple rename or cast only
transformvalue calculated, aggregated, joinedat least onerequired
createvalue with no sourcenoneoptional

2. From YAML to graph

The code splits each reference and turns it into a link between two columns. It does not read the SQL for this.

raw__ad_spend__metaads # ad_spend . spend
        contract          object    column

{"source": "raw__ad_spend__metaads", "sourceColumn": "spend",
 "target": "acquisition_monthly",    "targetColumn": "spend_amount"}

Table lineage is not declared: as soon as one column of B cites a column of A, the catalog draws A → B.

  1. YAML contractsthe sources of each column
  2. ↓
  3. make checkverifies references (separate step)
  4. ↓
  5. make catalogcreates the links, without verifying
  6. ↓
  7. index.html + colibri-manifest.jsonthe catalog and a copy of the data

Warning: make catalog and make publish verify nothing. A wrong reference ends up in the graph. Run make check first; CI does it before deploying from main.

3. Where to see it

  • Lineage tab: the + button and the arrows widen the graph. T = transformation, R = rename, P = copy.
  • SQL and description: Model Info, Columns tab, expand the column, turn on Expert mode.

4. Change lineage

  1. Edit the column in its contract.
  2. Bump the contract version. Changing the sources of a customer column is a breaking change: MAJOR version and review.
  3. Run make check, then make catalog-open.
  4. Open a pull request. Merging to main publishes, if the deployment token is configured.

5. What is not verified

make check verifies that columns cited by customer contracts exist, that there is no cycle and that required fields are filled in. For raw contracts, the external system is checked, not its fields. Nothing proves that the SQL uses the declared sources, or that the pipeline does what the contract says.

For developers: tools/build_catalog.py (build_manifest, render_html) and tools/validate_lineage.py.

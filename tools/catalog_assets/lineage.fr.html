Comment fonctionne le lineage

Le lineage est déclaré à la main dans les data contracts. Il n'est pas déduit du SQL, et rien n'est exécuté sur l'entrepôt.

1. Déclarer le lineage des colonnes dans le contrat

Chaque champ customer indique d'où il vient :

- name: first_order_at
  logicalType: timestamp
  physicalType: TIMESTAMP
  transformLogic: transform
  transformSourceObjects:
    - raw__orders__shopify#orders.created_at
  transformDescription: Plus ancienne date de création parmi les commandes du client.
  customProperties:
    - property: transformExpression
      value: MIN(created_at)

Une référence source s'écrit <contract_id>#<objet>.<property>. Les champs imbriqués utilisent le chemin complet.

transformLogicSourcesExpression SQL
mapexactement unefacultative, renommage ou cast trivial uniquement
transformau moins uneobligatoire, SQL BigQuery exact
createaucunefacultative

Les champs raw sont en map depuis le système externe (par exemple shopify_admin_api#...). Les champs techniques meta_loaded_at et meta_source_file sont en create.

2. Le lineage des tables est dérivé

Aucune déclaration séparée au niveau table. Un contrat dépend d'un autre dès qu'une de ses colonnes référence une colonne de celui-ci.

Les systèmes sources externes ne sont pas des contrats : ils n'apparaissent pas comme nœuds dans le graphe.

La légende du graphe est calculée à partir de la déclaration : Pass-through est un map qui garde le nom, Rename un map qui le change, Transformation un transform.

3. Contrôles avant publication

make check valide les contrats. Pour le lineage, il vérifie que :

  • chaque contrat, objet et property référencé existe ;
  • un contrat customer ne référence que des contrats raw ;
  • il n'y a pas de cycle ;
  • transformLogic, ses sources et son expression sont cohérents ;
  • chaque champ customer a transformLogic et transformDescription.

Les expressions SQL ne sont pas exécutées : une référence valide ne prouve pas que le pipeline fait réellement ce que dit le contrat.

4. Comment il est exposé

make catalog lit les contrats et écrit notamment :

  • colibri-manifest.json : contrats, colonnes, liens colonne à colonne et contrat à contrat, parents et enfants. D'autres outils peuvent le lire.
  • index.html : ce catalogue, un dashboard statique basé sur dbt-colibri (MIT).

Dans le catalogue, la vue lineage permet de suivre les tables et les colonnes en amont et en aval. Ouvrez une colonne et activez Expert mode pour voir la description de la transformation et son SQL.

Chaque push sur main lance les contrôles, reconstruit le catalogue et le déploie sur Cloudflare Pages si le jeton de déploiement est configuré.

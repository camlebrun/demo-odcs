Comment fonctionne le lineage

Le lineage dit d'où vient un chiffre et ce qui casse si on modifie un champ. Il tient en une règle : chaque source déclarée devient une flèche entre deux colonnes.

Data contract : un fichier YAML qui décrit une table. Raw : table recopiée d'un système (Shopify, GA4…). Customer : table calculée à partir des raw.

1. Déclarer une colonne

Exemple : spend_amount, la dépense publicitaire mensuelle, additionne Google Ads et Meta Ads.

# contracts/customer/acquisition/acquisition_monthly.odcs.yaml (extrait)
- name: spend_amount
  transformLogic: transform
  transformSourceObjects:
    - raw__ad_spend__googleads#ad_spend.metrics_cost_micros
    - raw__ad_spend__metaads#ad_spend.spend
    # + 8 (10 sources)
  transformDescription: Somme des micros Google Ads divises par 1 000 000 et de la depense Meta decimale, en EUR.
  customProperties:
    - property: transformExpression
      value: IFNULL(SUM(spend_eur), 0)
  • transformSourceObjects : toutes les colonnes utilisées, y compris pour filtrer ou joindre. C’est la seule chose qui dessine le graphe.
  • transformDescription : une phrase lisible par tous.
  • transformExpression : le SQL BigQuery. Il n’est ni exécuté ni comparé aux sources ; ici spend_eur est un nom intermédiaire.

mapvaleur recopiéeexactement unefacultatif : renommage ou cast simple seulement

2. Du YAML au graphe

Le code découpe chaque référence et en fait un lien entre deux colonnes. Il ne lit pas le SQL pour cela.

raw__ad_spend__metaads # ad_spend . spend
        contrat           objet     colonne

{"source": "raw__ad_spend__metaads", "sourceColumn": "spend",
 "target": "acquisition_monthly",    "targetColumn": "spend_amount"}

Le lineage des tables ne se déclare pas : dès qu’une colonne de B cite une colonne de A, le catalogue trace A → B.

  1. Contrats YAMLles sources de chaque colonne
  2. ↓
  3. make checkvérifie les références (étape séparée)
  4. ↓
  5. make catalogcrée les traits, sans vérifier
  6. ↓
  7. index.html + colibri-manifest.jsonle catalogue et la copie des données

Attention : make catalog et make publish ne vérifient rien. Une référence fausse passe dans le graphe. Lancer make check avant ; la CI le fait avant de déployer depuis main.

3. Où le voir

  • Onglet Lineage : le bouton + et les flèches élargissent le graphe. T = transformation, R = renommage, P = recopie.
  • SQL et description : Model Info, onglet Columns, déplier la colonne, activer Expert mode.

4. Modifier un lineage

  1. Modifier la colonne dans son contrat.
  2. Monter la version du contrat. Changer les sources d’une colonne customer est un changement cassant : version MAJOR et revue.
  3. Lancer make check, puis make catalog-open.
  4. Ouvrir une pull request. Le merge sur main publie, si le jeton de déploiement est configuré.

5. Ce qui n’est pas vérifié

make check contrôle que les colonnes citées par les contrats customer existent, qu’il n’y a pas de cycle et que les champs obligatoires sont remplis. Pour les raw, le système externe est contrôlé, pas ses champs. Rien ne prouve que le SQL utilise les sources déclarées, ni que le pipeline fait ce que dit le contrat.

Pour les développeurs : tools/build_catalog.py (build_manifest, render_html) et tools/validate_lineage.py.
